# THAI Please

โครงงาน React + Express + Prisma/MySQL: บิงโกเฉพาะบุคคล การบริจาคทดลอง และแต้มแลกรางวัล มี 4 เมนูหลัก หน้าหลัก / บิงโก / มูลนิธิ / รางวัล

## เริ่มในเครื่อง (ฐานข้อมูลเดิม)

ใช้ Node.js 24 และ MySQL 8 ขึ้นไป ค่าเชื่อมต่ออยู่ใน `backend/.env` ตาม `.env.example`

```sh
cd backend
npm ci
npm run db:generate
npm run db:upgrade
npm run dev
```

อีก terminal:

```sh
cd frontend
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดง กด **เปิดบัญชีทดลอง** เพื่อเริ่มด้วยเงินทดลอง 500 บาทและ 50 แต้ม ไม่ต้องใช้เลขบัตรประชาชน การอัปเกรดเพิ่มคอลัมน์/ตาราง ไม่มี reset หรือการลบข้อมูลเดิม

สำหรับ DB ใหม่ให้นำเข้า `thai_please_schema.sql` ก่อน แล้วรัน upgrade ข้างบน ไม่ใช้ไฟล์ seed ทับฐานข้อมูลเดิม

## Docker ทั้งชุด

```sh
docker compose up --build
```

เว็บ http://localhost:8080 และ phpMyAdmin http://localhost:8081 มี frontend/backend/MySQL/phpMyAdmin พร้อม volume เก็บ DB ไม่ต้องมี MySQL ใน host ค่า default ใช้สำหรับเดโมในเครื่อง ปรับ environment ของ compose เมื่อแชร์ให้คนอื่น

Docker daemon ในเครื่องที่ตรวจยังไม่ได้เปิด จึงตรวจผ่าน `docker compose config` และทดสอบแอปกับ MySQL ใน host แยกกัน ยังไม่ได้ยืนยันการ build image จริง

## AI และข้อมูลจำลอง

- ไม่มี API key: เลือกภารกิจด้วยกติกาและระบุ RULE_BASED
- กระดานแรกเป็นชุดเริ่มต้นร่วมกัน ระดับง่าย/กลาง/ท้าทาย 12/8/4 เพื่อเก็บพฤติกรรมตั้งต้น
- ตั้งแต่กระดานถัดไป AI เลือก 24 ภารกิจและเสนอระดับ 1–3 จากสถิติย้อนหลังรายผู้ใช้ 30 วันรวมวันนี้กับประวัติภารกิจ ไม่มีโควตาระดับ 12/8/4; backend ตรวจรหัสและเพดานระดับจากคลังก่อนบันทึก
- AI ที่ผ่านตรวจใช้ระดับที่เสนอจริง; ถ้า AI ใช้ไม่ได้ ระบบเลือกภารกิจจากกติกาสำรองและใช้ระดับ `supported_level` ที่คำนวณจากข้อมูลกิจกรรม พร้อมแสดง source ตามจริง ทุกกระดานมีภารกิจบริจาคตรงกลาง
- snapshot เก็บข้อมูล aggregate ที่ใช้สร้างกระดานและผลตรวจรูปแบบการเลือกไว้ตรวจย้อนหลัง; backend ขอให้ AI เลือกอย่างน้อย 2 ภารกิจจากทุกกลุ่มที่มีในคลังรวม SPEND และปรับจำนวนภารกิจร้านค้าตามประวัติ (4+ เมื่อมีร้านน้อย, ไม่เกิน 2 เมื่อใช้หลายร้าน); rubric เชิง heuristic ไม่ใช่หลักฐานว่า AI เพิ่มการใช้จ่ายหรือผลลัพธ์จริงได้
- การใช้จ่าย บริจาค เงินร่วมจ่าย คูปอง และสิทธิ์ลุ้นยังเป็นการทดลอง ไม่มีเงินจริง/การจับรางวัล/สิทธิลดหย่อนภาษี ThaiD ยังไม่เชื่อมและ endpoint เดิมปิดไว้
- มีภาพ/โลโก้เฉพาะ 28 องค์กรจากเว็บไซต์และลิงก์ที่ผู้ใช้เลือก ไม่มีความร่วมมือหรือการรับรองจากองค์กร

## ตรวจงาน

```sh
cd backend
npm test
cd ../frontend
npm run build
npm run lint
```

ชุดทดสอบแบบครบ flow ใช้ `npm run verify:app` ใน backend โดยชี้ DATABASE_URL ไป **เซิร์ฟเวอร์ทดสอบแยก** ไม่ใช่ฐานข้อมูลหลัก สคริปต์สร้างฐาน QA ชั่วคราวและลบเฉพาะฐานนั้นหลังจบ ภาพหน้าจอและรายงานสร้างไว้ใน docs/qa ซึ่งเก็บเฉพาะเครื่อง

## ผลรวม branch main กับ improveUxUi

- เก็บการทำงานบิงโกแบบ snapshot รายผู้ใช้/เดือน กระดานแรกชุดร่วม 12 ง่าย / 8 กลาง / 4 ท้าทาย กระดานถัดไปให้ AI เลือกภารกิจและเสนอระดับตาม profile จริงโดยไม่มีโควตา 12/8/4 พร้อมเก็บหลักฐาน aggregate และ rubric เชิง heuristic; รักษาการป้องกันธุรกรรมซ้ำ
- เพิ่มหน้า /profile จากแนวคิดฝั่ง main ใช้ยอดกระเป๋าเงินจริงของระบบทดลองที่ backend บันทึก ไม่เก็บยอดแยกใน localStorage และไม่อ้างว่าเชื่อมต่อ ThaiD
- นำการใช้คูปองจาก main มารวมกับ reward_redemptions เดิม เก็บเวลาใช้งานใน metadata และสถานะ USED ไม่ต้องเปลี่ยน schema ฐานเดิม แยกสิทธิ์ลุ้นกับคูปอง และตรวจเจ้าของ/หมดอายุ
- thai_please_schema.sql เป็น initial seed; backend/prisma/upgrades เป็นขั้นตอนเพิ่มคอลัมน์/ตารางสำหรับ functional ปัจจุบัน จึงต้องรัน npm run db:upgrade หลัง import seed ใหม่ ห้าม import seed ทับฐานข้อมูลเดิม
- ใช้ภาพใน frontend/public/assets ที่จับคู่มูลนิธิและสินค้าจริงแล้ว รวมถึงแก้วแบรนด์ที่ผู้ใช้เปลี่ยน ภาพจาก main ที่ไม่ได้ใช้อ้างอิงไม่ได้เพิ่มซ้ำเข้าชุด runtime
- เอกสารเสริม ผลทดสอบ และชุด Postman simulation เก็บเฉพาะเครื่องตาม .gitignore การทดสอบ AI HTTP ใช้ npm run verify:ai ได้เมื่อมีชุด simulation ในเครื่อง และไม่ยืนยันคุณภาพโมเดลจริงจาก mock


เพิ่มร้านค้าจำลองสำหรับทดสอบภารกิจ: รัน `npm run db:seed-shops` ในโฟลเดอร์ `backend` หลังนำเข้า schema และตั้งค่า `DATABASE_URL` แล้ว คำสั่งนี้เพิ่มเฉพาะร้านที่ยังไม่มี เก็บร้านและธุรกรรมเดิมไว้ และตรวจจำนวนร้านเทียบเป้าหมายในคลังภารกิจ ข้อมูลร้านอยู่ที่ `backend/prisma/seeds/demo-shops.json` ภารกิจตามช่วงเวลา/หลายวันยังนับจากเวลาธุรกรรมจริง


ทดสอบเส้นทาง AI จริง: รัน `npm run verify:ai:live` ใน `backend` หลังตั้งค่า Typhoon ใน `.env` คำสั่งใช้ข้อมูลสมมุติจาก `backend/examples/generate-board.mock.json` ไม่แก้ฐานข้อมูล เปรียบเทียบโหมดกฎสำรองที่ไม่เรียกโมเดลกับโหมด AI และตรวจว่ารหัสภารกิจจากคำตอบที่ผ่านการตรวจตรงกับกระดานสุดท้าย รหัสคำตอบและแฮชรายการเป็นหลักฐานตรวจสอบการทำงาน ไม่ใช่ลายเซ็นของผู้ให้บริการหรือผลประเมินความแม่นยำ โทเค็นประมวลผลของโมเดลแยกจากโทเค็นรางวัลในแอป
