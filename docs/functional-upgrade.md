## UX ที่เปลี่ยน

- ลดข้อความหลักบนหน้าจอ ซ่อนวิธีเล่น/เหตุผล AI/รายละเอียดรางวัลใน details หรือ dialog
- 4 เมนูหลักเหมือนกันทุกหน้า มือถือมีเมนูด้านล่าง
- หน้าแรกเน้นยอดเงินจริงทดลอง/แต้ม/ยอดให้ และกิจกรรมถัดไป
- Bingo แสดงชื่อสั้น ความคืบหน้า และความยาก มีมุมมองตาราง/รายการ
- มูลนิธิค้นหา/กรองได้ แสดงทีละ 6 รายการ ใช้โลโก้จากเว็บทางการ 4 แห่ง พร้อมลิงก์ต้นทาง
- รางวัลแยกแลก / ของฉัน / ประวัติ ไม่มี stock หรือวันจับรางวัลที่สร้างขึ้น
- บัญชีทดลองเริ่มได้โดยไม่ขอเลขบัตร ไม่แสดงว่ามีการเชื่อม ThaiD จริง

## กติกาความยาก

เดิมบังคับ 63 ระดับรวม / 24 ช่อง = 2.625 จึงออกระดับ 2–3 เป็นส่วนมาก รุ่นนี้ผู้ใช้ใหม่ได้ระดับ 1 ทั้งหมดก่อน ผู้มีประวัติได้อย่างน้อย 12 ช่องง่าย, กลางไม่เกิน 8 และยากไม่เกิน 4 โดยยังตรวจ target กับประวัติและคลังภารกิจ ไม่ใช้ mock profile ร่วมกันทุกคน

Source แยก `AI` กับ `RULE_BASED` จริง หากไม่มี key หรือผู้ใช้ยังใหม่จะเลือกตามกติกา เมื่อ AI ตอบผิดโครงสร้างแก้ได้หนึ่งครั้ง เมื่อ network/rate limit/timeout ให้ fallback โดยไม่ส่งคำขอซ้ำ

## การตรวจที่รันจริง

- `npm test` backend: 41 ผ่าน / 0 ล้มเหลว
- `npm run verify:app`: 16 กลุ่มตรวจผ่าน ใช้ MySQL QA ที่สร้างแยก มี server จริงและ Edge headless ทั้ง desktop 1440px กับ mobile 390px
- ตรวจ 5 หน้า + login: ไม่มี horizontal overflow หรือ pageerror ในเส้นทางที่ทดสอบ มีภาพใน `docs/qa`
- ปิด/เปิด backend ใหม่แล้วข้อมูลกระดานคงเดิม
- Postman simulation 1.76.0 + SDK จริงผ่าน HTTP: success, 429, JSON เสีย และ timeout; source และจำนวน retry ตรงกติกา ดู context ใน `postman/simulations/typhoon`
- frontend production build ผ่าน; lint exit 0 แต่มีคำเตือน React เกี่ยวกับ effect/date และ Fast Refresh บางจุด
- `docker compose config --quiet` ผ่าน ยังไม่ได้ build/run images เพราะ Docker daemon ใน host ไม่ได้เปิด
- ฐานข้อมูล `thai_please` เดิมเพิ่ม 11 คำสั่ง DDL แบบ additive จำนวนข้อมูลก่อน/หลังคงเดิม: users 3, transactions 1, donations 0, bingo_boards 8, token_transactions 3; ไม่ reset DB และไม่แก้บัญชีเดิม

## ทำซ้ำการตรวจ

`npm run verify:app` จาก backend ต้องใช้ MySQL user ที่สร้าง DB ทดสอบได้ และ Chromium/Edge พร้อมใช้งาน Script สร้างชื่อ DB ใหม่ทุกครั้งและลบเฉพาะ DB ที่ตัวเองสร้างเมื่อจบ ตั้ง `KEEP_QA_DB=true` หากต้องการเก็บไว้ตรวจ ตั้ง `BROWSER_EXECUTABLE` หาก browser อยู่ตำแหน่งอื่น Linux ใช้ `npx playwright install chromium` ก่อน

การทดสอบจบกระดานใช้ fixture แก้ snapshot เฉพาะใน DB QA เพื่อทดสอบ claim/accept โดยไม่ต้องรอภารกิจหลายวัน ไม่ใช่ endpoint ลัดในแอป และไม่ได้พิสูจน์ว่าใช้เงินจริงหรือทำภารกิจครบหลายวันจริง

## ขอบเขตที่ยังเป็นการสาธิต

เงินที่ใช้/บริจาคเป็นยอดทดลอง ไม่มีการโอนเงินจริงถึงร้านหรือมูลนิธิ สิทธิ์รางวัลบันทึกใน DB แต่ไม่มีการส่งสินค้า ใช้คูปองกับร้านจริง หรือจับรางวัลจริง ไม่มี e-Donation/ใบภาษี/ThaiD integration และยังไม่ได้วัดคุณภาพการเลือกภารกิจกับ Typhoon จริงด้วย key ผู้ใช้ จึงไม่อ้างผลการประเมินโมเดลที่ยังไม่ได้ทำ
